# ableton_live_mcp

[![CI](https://github.com/cmdiego/ableton_live_mcp/actions/workflows/ci.yml/badge.svg)](https://github.com/cmdiego/ableton_live_mcp/actions/workflows/ci.yml)

A simple MCP server for Ableton Live 12 that uses the standard Live API + Max for Live.
It lets Claude (or any MCP client: OpenCode, Codex, Copilot, Cursor, Gemini CLI) organize, compose, mix
and master your tracks.

```
Claude (Desktop / Code) ──MCP stdio──▶ ableton-mcp server ──JSON lines, TCP 9877──▶ AbletonMCP Remote Script (in Live)
```

## Setup

1. `uv sync`
2. `scripts/install_remote_script.sh`, then restart Live and pick **AbletonMCP** under
   Settings → Link, Tempo & MIDI → Control Surface (Input/Output: None).
3. Connect your AI client. Claude Code (`.mcp.json`) and OpenCode (`opencode.json`) pick it up
   from this repo. For Codex, Claude Desktop, Copilot, Cursor and Gemini CLI, see [docs/clients.md](docs/clients.md).
4. Export mixes and stems for analysis into [agent/exports/](agent/README.md), the assistant's working folder.
5. Check it: `uv run python scripts/smoke.py` (use a scratch set; it adds and removes a test track).

## Using it

Just ask in plain language ("write a funky bassline for the chords in scene 2", "why does my mix sound
muddy?", "add a breakdown before the second drop"). Claude picks the tools.

- **Workflow prompts** (MCP prompts; in Claude Code they appear as `/mcp__ableton__…` commands):
  `organize_session`, `write_part`, `mix_check`, `arrangement_review`, `master_track`.
- **Resources** a client can attach as context: `ableton://session`, `ableton://arrangement`,
  `ableton://agent-files`, `ableton://api-notes`.
- **One undo per request:** multi-step changes go through the `batch` tool, so one Undo in Live
  (or the `undo` tool) reverts all of it.
- **Mastering:** export your mix into `agent/exports/`, then `plan_master` (target: streaming, apple,
  loud, club, a reference track, or custom) and `apply_master`. Export again and re-run `plan_master` to
  check the real result; it corrects until it's within ±0.5 LU and under the true-peak ceiling.
- **Live audio (Suite):** `analyzer(action='install')` puts the *AbletonMCP Analyzer* Max for Live device on
  the master. `capture` records Live's real output (32-bit float, optionally from a bar with playback
  started for you) and analyzes it like an export; `meter` gives live peak/RMS. Mastering can then iterate
  on captures (`plan_master(path='latest_capture')`) without manual exports. The device is generated by
  `m4l/build_analyzer.py` from Ableton's own template.
- 35 tools in total, grouped as set / compose / sound / mix / audio / arrangement (see the server
  instructions in `src/ableton_mcp/app.py`).

## Development

- `uv run pytest`: runs the whole stack against a fake Live set (`tests/fake_live.py`), plus
  client-compatibility checks. New tools must follow the rules in [docs/clients.md](docs/clients.md).
- The Remote Script is deliberately thin (generic `lom_get/set/call/query` plus note commands).
  Most features live in `src/ableton_mcp/` and need no Live restart.
- After editing `remote_script/AbletonMCP/handlers.py` or `lom.py`, hot-reload them with
  `uv run python -c "from ableton_mcp.live_client import LiveClient; print(LiveClient().call('reload'))"`.
  For changes to `surface.py`, `server.py`, `dispatcher.py` or `__init__.py`, switch the control surface to None and back
  to AbletonMCP (it reloads all its modules on start). Edits to `__init__.py` itself only load after restarting Live.
- Live's log: `~/Library/Preferences/Ableton/Live 12.4.6/Log.txt` (grep `AbletonMCP`).
